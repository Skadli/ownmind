# 007 主键与时间的存储

- 状态：已采纳
- 日期：2026-10-15

## 问题
全项目要统一主键类型和时间存法；表上线后再改代价很高。

## 决定
- 主键：UUIDv7，SQLite 里以 TEXT（36 字符带连字符）存，应用内用 `ownmind_kernel::new_id()` 生成。
- 时间：UTC Unix 毫秒，INTEGER 列，`ownmind_kernel::now_ms()` 获取；界面按主人时区显示。
- 表用 SQLite `STRICT`，类型写错直接报错。

## 考虑过的方案（及放弃原因）
- 自增整数：暴露数量；以后 App 离线新建数据会冲突。
- UUIDv7 存 BLOB：省空间，但日志、URL、手查数据库都不可读；单人数据量下空间不是问题。
- 时间存 RFC3339 文本：可读，但比较和排序依赖格式一致，易出错。

## 后果
ID 字符串可以直接出现在 URL 和日志里；按 ID 排序约等于按创建时间排序。
