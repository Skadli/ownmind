
# 演进

## 体检清单
- 依赖：module.yaml 依赖是否增多、有无绕过 api 的调用迹象
- 浅模块：接口几乎和实现一样复杂的模块 → 合并或加深
- 热点：修改频繁且复杂度高的文件 → 拆分或简化候选
- 死代码：无调用、无测试覆盖的代码 → 删除
- 数据：无人读的列、过宽的表、缺失的唯一约束
- 文档：过时的 README、与代码不符的 architecture.md
- 规则：长期没有拦截记录的规则与门禁

## 重构方式
- 小重构：一张票。
- 宽重构：expand（加新形式）→ migrate（分批迁移调用方，每批一张票）→ contract（删旧形式）。每一步 CI 都是绿的。

## 产出
体检报告（具体到文件和模块）+ 放入下个迭代的简化/重构票。
