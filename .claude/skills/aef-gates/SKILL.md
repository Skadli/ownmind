# 门禁

## 目标
规则由脚本执行，不靠 AI 自觉；每个门禁都证明过自己会变红。

## 形状
```
.aef/gates/<name>/
  run              # 可执行，参数为要检查的根目录，通过返回 0
  fixtures/bad/    # 至少一个违规样例
  README.md        # 规则、理由、失效条件
```
`.aef/gates/run-all.sh` 先对每个门禁的 bad 样例运行，必须失败；再对仓库运行，必须通过。

## 优先实现的门禁
1. 类型检查、lint、格式
2. 模块边界：只能导入其他模块的 api/；依赖必须在 module.yaml 的 depends_on 中；无环
3. 测试（集成测试使用真实数据库容器）
4. 迁移不可变：已合并迁移的哈希不变
5. 空库迁移 + 从上一版本升级
6. 表归属：模块代码只写自己 owns_tables 中的表
7. 硬编码文案（启用国际化时）
8. 文档同步：模块 api/ 变化时 README 也必须变化
9. 契约差异：OpenAPI 破坏性变化必须附升级说明

能用现成工具就用（ArchUnit、dependency-cruiser、go-arch-lint 等），只在没有工具时自己写脚本。

## 判断一条规则该不该变成门禁
- 违反代价大、靠人难发现 → 门禁
- 口味问题 → AGENTS.md 一句话
- 只出现过一次的错误 → 先不管，再出现再说

## 完成标准
新门禁有 bad 样例、在 CI 中运行、README 写明理由和失效条件。
