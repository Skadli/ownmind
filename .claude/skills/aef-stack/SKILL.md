# 定栈并生成说明文件

AEF 的其他技能只写通用约束。具体怎么做（用哪个工具、文件放哪、命令是什么）只在用户确定后写进 docs/stack.md。没定之前，AI 不替用户选型。

## 1. 讨论（调用 aef-grill 的问法：一次一问，附推荐和理由）
按顺序确认，已确定的跳过：
1. 后端语言与框架
2. 数据库与迁移工具
3. 前端框架与组件库（是否需要前端）
4. 项目结构：单仓还是多仓；模块目录怎么放
5. 部署方式：单机 docker compose、云平台、k8s
6. 测试工具：单元、集成（是否用数据库容器）、端到端
7. 门禁工具：lint、模块边界检查用什么实现
推荐时优先：用户已熟悉的 > 生态成熟、AI 训练数据多的 > 新潮的。每个选择的理由写一句话。

## 2. 生成
- **docs/stack.md**（以后所有 AI 读它，控制在 200 行内）：
  - 选型表：类别、选择、理由、版本
  - 目录结构：一个模块在这个栈里长什么样（真实路径）
  - 常用命令：启动依赖、db-init、运行、测试、门禁
  - 通用规则在本栈的落地方式：模块边界如何表达与检查、迁移文件命名与位置、种子数据怎么写、事务与错误处理惯例、配置读取方式
  - 每条落地方式附一个最短的代码示例
- **AGENTS.md**：填实“命令”和“目录”两段，并加一行“技术细节见 docs/stack.md”。
- **决策记录**：一条“技术栈选择”，写明考虑过的方案。
- **门禁**：把 .aef/gates/ 中需要的门禁换成本栈的真实实现（每个带 bad 样例）。

## 3. 更改技术栈
写决策记录 → 更新 docs/stack.md → 检查门禁是否仍有效。不要在多处重复写技术细节，其他文档只引用 docs/stack.md。

## 完成标准
用户确认选型；一个新会话只读 AGENTS.md 与 docs/stack.md 就知道每类任务用什么工具、文件放哪。
