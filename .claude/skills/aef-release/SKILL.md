# 发布

1. 汇总自上次发布以来合并的 PR、迁移、配置变更。
2. 版本号：语义化版本；有破坏性 API 或数据变更时升主版本（或在 1.0 前升次版本）。
3. 写升级说明（docs/upgrades/vX.Y.Z.md）：迁移列表、是否需要停机、新增或变更的配置项、破坏性变更与应对。
4. 预发环境演练：从生产当前版本的数据副本升级，跑冒烟测试，演练回滚。
5. 生产：备份 → 执行迁移 → 发布新版本 → 冒烟测试 → 观察指标。
6. 回滚：代码回滚到上一版本（迁移已保证兼容旧代码）；数据问题用向前修复或备份恢复。
7. 写发布记录：版本、时间、迁移结果、验证结果、问题。

## 发布前加固
首次上线或重大版本前，按 harden.md 过一遍安全、性能、可观测、备份恢复。
