# 计划与切票

## 目标
本迭代 5–15 张票，每张是一个会话能完成、能独立验证的垂直切片。

## 里程碑 spec（进入新里程碑时写一次）
.aef/milestones/MN-<名称>.md（可选，里程碑简单时直接写在 state.md）：目标、功能清单（用户视角）、验收标准、涉及模块、数据变更、明确不做。

## 切票
- 先读代码，再切票。票里引用的文件、接口、表必须真实存在或在本票中创建。
- 垂直切片：每张票贯穿需要的层（迁移 → 后端 → 前端 → 测试），完成后能演示一个行为。
- 跨模块功能先出一张“定接口”的票（api/ 中的接口、DTO、契约测试）。
- 破坏性数据变更按 expand → migrate → contract 拆成多张票，各自可发布。
- 声明阻塞关系；无阻塞的票可以并行。
- 只切本迭代；后续迭代只保留里程碑中的一句话。

## 票的格式
写到 .aef/tickets/NN-<标题>.md，使用 .aef/templates/ticket.md。验收条件必须能被测试验证，不写“代码整洁”这类无法判定的条件。

## 完成标准
用户批准票列表；state.md 写入本迭代票列表与第一张票。
