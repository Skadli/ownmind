# 实现一张票

## 节奏
1. 读票、相关模块的 module.yaml 与 README，确认验收条件。
2. 选一条验收条件写失败的测试（优先通过模块 api 的集成测试，使用真实数据库容器）。
3. 写最少的代码让它通过。
4. 重复 2–3 直到验收条件全部覆盖。
5. 重构：删重复、加深模块、命名对齐 GLOSSARY。
6. 跑本地门禁（只跑覆盖改动的那部分，全量交给 CI）。
7. 调用 aef-review；处理阻塞意见。
8. 写 PR 描述：做了什么、对应票、证据（测试与迁移结果）、爆炸半径、是否可逆。
9. 更新 .aef/state.md（交接）。

## 测试原则
- 测行为，不测实现细节；测试通过模块 api，不穿透 internal。
- 只 mock 外部、昂贵或不确定的边界（第三方 API、时钟、随机数）；数据库用真的。
- 验证结果要看真实状态（重新查库、重新读文件），不信函数自己的返回描述。
- 没被任何测试覆盖到的代码，先考虑它是不是该删。

## 编码原则（反防御性编程）
- 只在系统边界校验输入；模块内部信任类型与调用方。
- 错误大声失败，不吞异常。
- 不为不可能的状态兜底，不为假想需求抽象，不留兼容垫片。

## 不要做
不改票外模块；不修改已合并的迁移；发现票外问题写进 state.md。

## 遇到 bug
按 diagnose.md：先复现，再定位，最后留下回归测试。

## 小改动
一两个文件、无数据变更、无接口变化的改动，可以跳过切票和两轴评审，直接改 + 测试 + 门禁。
